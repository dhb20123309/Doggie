功能概述
在 Cascade（三段式） 模式下，TTS（文本转语音）是对话链路的第三段，也是 AI 机器人的“嗓音”：接收 LLM 流式输出的回复文本，实时合成语音并回传到 TRTC 房间播报，同时支持被打断。
TTS 段采用 Provider + Params 接入模式，支持：
TRTC 自研 TTS（trtc ，默认）：即开即用，无需开通第三方服务，推荐绝大多数场景直接使用。
第三方 TTS（minimax  / azure ）：满足指定音色、特定厂商音质的需求。
自定义 TTS（openai）：自研 TTS、私有化部署 TTS，基于 OpenAI TTS 标准协议对接。
说明：
S2S（端到端）模式下，音频由端到端模型直接生成，不存在独立的 TTS 段，无需配置 TTSConfig。

第三方 TTS 接入
将 Provider  设置为对应厂商标识（ minimax / azure ），并在 Params 中传入该厂商的专属参数（鉴权、模型、音色、语速等），参数规范以对应厂商文档为准。如需接入其他 TTS 厂商，请联系商务。
Minimax 接入示例（Provider = minimax）
点击查看 Minimax 官网文档 。
配置示例：
"TTSConfig": {
"Provider": "minimax",
"Params": "{\"provider\":\"minimax\",\"api_key\":\"<your-api-key>\",\"model\":\"speech-2.6-hd\",\"url\":\"https://api.minimaxi.com/v1/t2a_v2\",\"voice_setting\":{\"voice_id\":\"male-qn-qingse\"}}"
}

自定义 TTS 接入（Provider = openai）
客户可提供自研 TTS、私有化部署 TTS 或第三方 TTS 服务作为 AI 对话的语音合成模块。接口协议基于 OpenAI TTS 标准协议构建，并针对实时对话场景做了必要扩展（如 PCM 流式输出、采样率/声道控制）。

接入要点
1.
TRTC 侧对 Params  做 JSON 合法性校验但不解析内部字段语义，具体字段映射关系由 AI 后台的自定义 TTS 适配器实现。
2.
建议业务侧 TTS 服务做好流式输出，避免首包延迟过大影响对话体验。
3.
自定义 TTS 服务需按协议返回 HTTP 200 + PCM 二进制流（Chunked），非 200 响应视为合成失败。
音频回传房间
TTS 合成的音频由后台通过回推机器人推入 TRTC 房间，回推机器人通过 AgentConfig.TTSPushRoomParams 指定：
字段名
必选
类型

"AgentConfig": {
"UserId": "ai-bot-001",

对话机器人（AgentConfig.UserId）与回推机器人（TTSPushRoomParams.UserId）需使用不同的用户 ID，客户端订阅回推机器人的音频流即可听到 AI 的回复。

注意事项
1.
TTS 配置不支持热更新：任务创建后无法通过修改任务接口变更 TTSConfig；如需更换音色或厂商，请结束当前任务并重新创建。
2.
仅 Cascade 模式需要配置：S2S 模式由端到端模型直接生成音频，无需 TTSConfig 。
3.
音色与语言需匹配：VoiceId 需填写与对话语言对应的音色 ID，语言与音色不匹配会导致合成失败或发音异常。
4.
打断配合：TTS 播报中收到打断指令（自动 / 手动 / 关键词打断）会立即停止播放并清空待播队列，详细参见 （客户端）打断指令。
