# 需求文档

## 1. 应用概述
在现有「虚拟手机恋爱模拟器」中新增**语音通话 App**：拨给当前选中角色，按键开始录音、再按结束（第一版不做自动连续监听），录音转成文字后交给该角色原有 LLM 链路生成回复，再用 MiniMax T2A 以角色绑定的 voice_id 合成语音播放——形成"说→听→答→播"的完整电话闭环。

## 2. 分步验收计划（严格按 A→B→C→D，每步单独编译 + 真机测试方法，不一次实现全部）

### 步骤 A：请求麦克风权限并录音
- 行为：通话界面出现大圆按钮「开始录音 / 结束录音」两态；首次点击申请 `getUserMedia({audio})` 权限；录音中显示时长与波形条；结束后得到一段符合 MiniMax STT 接口要求的音频格式（浏览器端重采样编码为 16kHz/单声道 WAV）。
- 失败处理：拒绝权限、无麦克风设备分别给出人话提示，按钮置灰。
- 编译门禁：`pnpm run build` + `npx tsc --noEmit` 通过。
- **真机测试方法**：手机 H5 打开通话页 → 点开始录音（浏览器弹权限，允许）→ 说几句话 → 点结束 → 界面显示"录音 N 秒 · 可试听"，能回放刚才的声音即通过；再走一次拒绝权限路径，应显示引导文案而非白屏或报错崩溃。

### 步骤 B：MiniMax STT 转文字
- 行为：录音结束后调用 MiniMax speech-to-text 接口（复用设置页已有的 minimaxKey/minimaxRegion，国内打 api.minimaxi.com、国际打 api.minimax.io），返回**转写文本 + 置信度**上屏；转写失败必须返回明确原因（Key 无效/区域不符/音频为空/格式不支持/限流等逐类翻译成人话）。
- 编译门禁：同上。
- **真机测试方法**：录一段清晰中文短句 → 结束录音 → 数秒内屏幕显示转写文字和置信度；故意填错 Key 或切错区域再测，应显示对应分类错误原因而不是笼统"失败"。

### 步骤 C：把通话上下文交给当前角色生成回复
- 行为：本轮转写文本作为用户消息，带入**角色卡人设 + 生效世界书 + 最近聊天记录**，走角色原有 LLM 链路（buildSys/toHistory/chatCompletion 同一套协议，不清空私聊记忆）生成回复文本，显示在通话气泡里，同时写入该会话记录（标记为通话产生）。
- 编译门禁：同上。
- **真机测试方法**：对角色说"你现在在干嘛" → 转写完成后出现符合人设的口语化回复；退出通话进聊天页，这条问答在聊天记录可见（记忆互通）；切换不同角色各测一次，回复风格随角色变化。

### 步骤 D：MiniMax TTS 播放（使用当前角色绑定的 voice_id）
- 行为：回复生成后调用既有 t2a_v2 合成，voice_id 优先取当前角色绑定的 voiceId（官方音色/克隆音色均可），拿到音频后本地播放；播放中显示声波动画，可手动停止；角色未绑定音色时回落通道默认音色并在界面标注。
- 编译门禁：同上。
- **真机测试方法**：完成一轮 C 后自动出声，音色与该角色在设置里绑定的音色一致（换角色声音应变）；未绑音色的角色回落默认音色仍正常出声。

## 3. 页面结构与功能说明
```
桌面 App 网格
└─ 语音通话 App（全屏）
   ├─ 顶栏：返回 + 当前角色名/头像 + 通话状态
   ├─ 角色选择条（多角色快速切换）
   ├─ 主区：对话气泡流（我说的话=转写文本 / TA=回复文本）
   ├─ 录音按钮：开始/结束两态 + 时长 + 波形
   └─ 底部：置信度徽标 / 失败原因条 / 播放控制
```

## 4. 业务规则
- 录音只由按键启停，无任何后台持续监听、无自动 VAD；单段录音上限 60 秒，超时自动结束。
- STT/TTS 共用设置页已有 MiniMax Key 与区域配置，不新增第二套密钥体系。
- 通话内容与文字聊天共享同一份会话记忆（互通），通话产生的条目带独立标记样式。
- 所有 API 失败必须落到"人话原因 + 可重试"，禁止静默失败。

## 5. 异常与边界
| 场景 | 处理 |
|---|---|
| 用户拒绝麦克风权限 | 提示去浏览器设置开启，按钮置灰 |
| 录音时长 0 秒就结束 | 不发 STT，提示"没听到声音" |
| STT 返回空文本 | 提示重新录制，不进 LLM 链路 |
| LLM 未配置/调用失败 | 沿用现有退避重试一次，仍失败显示原因+重试按钮 |
| 角色未绑定音色 | 回落通道默认音色并在界面标注 |

## 6. 验收标准（可逐条勾选）
- [ ] A：按键启停录音成功，产物为合规格式音频且可试听
- [ ] B：真实 MiniMax Key 下转写出文本+置信度；错误 Key 给出分类原因
- [ ] C：回复符合当前角色人设，进聊天页记忆互通可见
- [ ] D：角色绑定 voice_id 正确出声；未绑定回落默认音色
- [ ] 四步各自编译通过、每步交付附真机测试方法
- [ ] 全程无自动 VAD、无后台监听

## 7. 本期不实现
- 自动语音活动检测（VAD）连续监听、实时流式 STT/TTS、多人通话、通话录音留存云端、悬浮来电通知形态。

## 8. 风险与说明
- MiniMax STT 接口协议以官方文档为准，接线前先实测校正（此前 T2A 也经历过协议对齐）；若账号未开通语音识别服务会返回权限类错误，届时如实告知。
- 网页形态限制：麦克风需 HTTPS 环境；浏览器权限弹窗由系统浏览器接管，无法自定义。
