# 需求文档

## 应用概述
在手机 App「世界书」中新增两项能力：①**一键导入文档**——选择 txt / md / docx 文件，自动解析成多条世界书条目；②**插入深度调节**——每条世界书可单独设置注入 AI 提示词的深度档位（常驻 / 浅层 / 深层），控制它是每次都全量喂给 AI，还是只在聊天聊到相关话题时才出现。

## 用户与使用场景
- 手里有一份设定文档（Word/Markdown/纯文本），想直接搬进世界书，不用一条条复制粘贴
- 背景设定太多怕 AI 记混、也怕费 token，希望"核心设定常驻、次要设定聊到了才提"

## 页面结构与功能说明
### 1. 世界书列表页（WorldBookApp）
- 顶栏「+」旁新增**导入按钮**（文件夹图标）→ 进入导入预览页：
  - 选择文件（accept: `.txt` / `.md` / `.docx`）
  - 解析规则：按 `##` 二级标题分节，每节一条 local 条目（沿用现有 parseWorldBookMd 逻辑）；无分节则整篇作为单条；docx 会识别加粗/标题样式行作为分节标题
  - 预览卡片列表：显示将生成的条目名 + 内容摘要 + 字数，可勾选/取消要导入的条目
  - 底部统一选择**默认插入深度**（三档分段控件）后点「导入 N 条」，成功 toast 提示并回列表
- 条目卡片上显示当前深度徽章（📌常驻 / 🕐触发 / 🌊深层）

### 2. 条目编辑器（BookEditor）
- scope 切换下方新增「插入深度」三档选择 + 一句话说明：
  - **📌 常驻（深度0）**：每次回复都完整写进设定里，最稳但最费字——适合世界观、关系等核心设定
  - **🕐 触发（深度1，默认）**：从正文自动提取关键词（名称 + 内容里的 2~4 字词组，上限8个），只有你最近的话或 TA 的回复触发了关键词，这条设定才会被喂给 AI——省 token 不硬塞
  - **🌊 深层（深度2）**：平时只以"条目名"出现在目录里，AI 觉得需要时会主动要求查看，届时该条全文随下一条消息注入（模拟酒馆"插入深度"效果）
- 触发档下可点开「编辑触发词」手改自动提取的词

### 3. 数据契约（src/lib/worldbook.ts）
- WorldBook 新增可选字段：`depth?: 0 | 1 | 2`（旧存档缺省视为 1，行为温和）、`keywords?: string[]`（仅 depth=1 用，空则现算）
- 新函数：`autoKeywords(wb)`（名称分词 + content 高频 2~4 字中文词组去重取前 8）、`buildWorldSectionV2(books, recentText, requestedIds)`——把生效条目拆成三段拼接：常驻全文段 + 命中触发的全文段 + 深层目录段（目录带指令"若需某条详情，在回复末尾输出 [查设定:名字]，不要复述目录"）
- 新解析器：`parseDocxBuffer(arrayBuffer)`——浏览器端解 docx word/document.xml，段落级提取文本，w:pStyle 为 Heading*/Title 或含 w:b 加粗的行标记为标题行，产出与 parseWorldBookMd 相同的 `{name, content}[]`

### 4. 注入链路（RoleChatApp buildSys）
- buildSys 内把 `buildWorldSection(activeBooks)` 换成 `buildWorldSectionV2(activeBooks, 最近3条消息文本, requestedIntroIds)`
- 深层按需展开：回复解析处（仿表情标记）识别 `[查设定:名字]` → 把对应条目 id 记入本会话待注入集合（内存 state 即可，不落库），下一轮 buildSys 将其全文并入常驻段并清除标记；日志 `[worldbook] deep request 名字 → 已解锁`
- 剧情模式与私聊共用同一 buildSys，自动生效；fireOne 主动消息同样走 V2

## 业务规则
- 导入不覆盖同名旧条目，重名自动加序号后缀；单次导入上限 50 条
- 全局(global)条目也可设深度，但常驻档永远注入不受触发过滤影响
- 触发匹配范围 = 最近 3 条消息（含玩家与角色），大小写不敏感、子串包含即命中
- docx 解析失败（加密/损坏）时红字提示改用 md/txt，不影响已有条目

## 异常与边界情况
| 场景 | 处理方式 |
|------|---------|
| 文件为空/全是图片 | 预览页提示"没解析出文字内容"，禁用导入按钮 |
| docx 是扫描件无文字 | 同上提示 |
| 单节超 2500 字 | 截断加省略号（沿用现有规则） |
| 深层条目从未被请求 | 目录最多列 20 条，超出按导入顺序截断 |
| 旧数据无 depth 字段 | 视为触发档，且无 keywords 时现算，行为不变差 |
| AI 输出的 [查设定:x] 名字不存在 | 忽略，当普通文字滤掉，不裂进界面 |

## 验收标准
1. 世界书页点导入 → 选一份含多个 ## 分节的 .md，预览列出各节，勾选后导入，列表出现对应条目且默认"触发"档
2. 选一份 .docx（Word 里用标题样式分了节），能解析出同样的条目
3. 把某条设为"常驻"，在与该条内容无关的话题下聊天，AI 仍能引用它；设为"触发"且不含触发词时不注入（控制台 `[worldbook] section global/local/deep` 日志可见三段字数）
4. 设一条"深层"，对它说"介绍一下XX设定"，AI 回复末尾出现查设定标记被系统消化，下一条回复 AI 能讲出该条细节
5. 编辑器改深度即时保存，重进世界书徽章显示正确；刷新页面配置不丢

## 回归与兼容风险
| 风险点 | 是否破坏现有行为 | 兼容策略 |
|--------|----------------|---------|
| 旧存档无 depth/keywords | 否 | 缺省 depth=1，无词现算 |
| buildSys 第三参 memeText 与热梗注入顺序 | 否 | 世界书段仍插在热梗段之前，格式向后兼容 |
| 表情标记解析器与查设定标记共存 | 低 | 独立正则各自解析，互不误吞 |
| 预置《周氏双子》local 条目 | 否 | 迁移时保持原样，仅显示为默认触发档 |
