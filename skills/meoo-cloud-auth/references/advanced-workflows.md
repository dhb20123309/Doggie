# Meoo Cloud Auth

Web/H5/Expo 真实认证的统一入口；负责密码登录、注册确认、Session、密码恢复、页面守卫及原生 MFA。第一因子选择由 `skills/meoo-cloud/references/auth-routing.md` 负责；新建或修改数据/RLS 时读取 `skills/meoo-cloud/references/auth-data-baseline.md`。本技能按已确认结论接线。 用户明确使用邮箱注册时优先选择 `auth_email_password`，使用手机号注册时优先选择 `auth_sms_password`；未提验证码不等于选择基础账密。普通用户名兼容邮箱／手机号形状、资料联系方式及存量模式的边界见该路由文档。

## 认证页面结构

新项目默认使用独立的 `/login`、`/register`、`/reset-password` 路由，每页固定登录／注册／恢复模式；只生成本轮需要的页面，回调页仅在认证方式需要时创建。不自行生成 `/auth?mode=...` 组合认证页。只有用户明确要求组合入口，或已有项目已采用组合入口且本轮沿用时才保留；不为此强制迁移存量路由。

注册和恢复页面及祖先布局不能仅凭 Session 存在跳转；注册完成身份核对及必要资料收尾后导航，恢复完成改密并退出恢复会话后返回登录。

业务页是否需要登录由产品需求决定，不由 `/app` 等路径名决定。游客与登录用户均可访问的页面不套整页 AuthGate，按身份展示可选能力；只有明确要求登录的页面或全部子页均需登录的布局才使用 AuthGate。混合访问与退出行为见 [接线示例](auth-route-plan.md#按页面访问语义选择守卫)。

## 先确认范围

1. 确认 `meoo-cloud` 已加载（未加载则先加载），模式未确认时读取其 `references/auth-routing.md`；新建或修改用户模型才补 `references/auth-data-baseline.md`，再执行初始化或编写认证代码。确认唯一 `authImplementationSop`：`basic_auth`、`auth_email_password` 或 `auth_sms_password`；MFA 是附加的 `authSecondFactorSop`。不根据输入框名称或非空字段猜模式。`basic_auth` 中合法邮箱直接使用，其他不含 `@` 的账号映射为虚拟邮箱；含 `@` 的非法输入拒绝。页面传原始 `username`，注册和登录共用解析规则；格式校验和存量兼容按 `basic_auth.md` 执行，不因此切换 SOP 或启用验证码、确认、恢复能力。
2. 定位现有 Client、Auth 状态源，以及当前行为涉及的页面、路由和权限入口；先核对公共接口，修改内部行为或排障时才沿失败链路读取实现。已有明确模式且本轮只修接线时直接沿用，不重新选择通道或启动迁移。涉及从虚拟邮箱升级为真实邮箱或真实手机号，先执行该文档的存量升级闸门；用户未确认迁移或保留方案前不实施。用户已明确授权的范围无需重复确认。
3. 页面按已确认模式生成输入项：`basic_auth` 只生成“用户名 + 密码”，邮箱模式生成“邮箱 + 密码”，短信模式生成“手机号 + 密码”；标签、占位符、输入类型、校验和错误文案遵守 [工程接入](integration.md#页面输入契约)。模板兼容邮箱／数字账号不等于可以生成混合登录入口。
4. 按本轮范围列出 **注册提交、注册确认、密码登录、普通退出、密码恢复** 的实现位置和验收项。迁移时检查所有已有入口；未提供且不涉及的注册入口记为不适用，不为恢复或测试新增注册功能。任务恢复后核对实际接线，不能凭模板回执判断完成。
5. Web 新建认证入口或调整认证布局时，先按 [认证路由接入顺序](auth-route-plan.md) 确定实际 URL、访问要求、父布局和导航负责人，接通并验证一个符合需求的最小业务页面，再扩展业务页；不为认证接入额外创建受保护页面，已有结构的局部修复只验证受影响链路。

仅静态/Mock 页面和小程序认证不适用；仅诊断故障改读 `skills/meoo-cloud/references/auth-diagnosis.md`。不实现纯验证码免密登录或邮箱 OTP MFA：明确说明限制，等待用户选择支持的方案。验证码链路或 MFA 类型不明确时，只澄清缺失选择，不默认邮箱、短信、TOTP 或 Phone。

## 工程入口与实施

- 普通业务接入按本 Skill、对应流程及示例使用模板，无需读取 `AuthProvider.tsx`、`auth-actions.ts`、`AuthGate.tsx` 等内部源码。先核对项目 `src/features/supabase-auth-runtime/index.ts` 的实际导出及目标文件存在；使用恢复或 MFA 等子路径时只核对该模块存在及所需导出，不展开实现。
- 参数、返回值或限制不明确时查接口速查；只有修改模板、排查模板内部行为，或发现项目实现与文档契约不一致时，才按下表读取相关函数及直接依赖。页面接线、认证请求或服务配置异常先检查对应调用方与实际错误，不自动展开全部模板源码。
- 入口或导出缺失先搜索已有等价实现并核对其接口；确需补齐模板或核对实现差异时，才读取对应的只读参考文件。
- `template-reference` 只读，不得 Edit/Write 或作为业务 import。参考存在不代表已经落盘；确认无等价实现且模板复制未在进行后，才按当前平台补齐必要项目文件并核对导出。
- 复用平台生成的 `src/supabase/client.ts`，不修改它、不另建 Client。未初始化先按 meoo-cloud 流程执行 `meoo-cli cloud init -d "项目描述"`；不直接写 `auth.users`、生成密码哈希或伪造身份绕过认证。
- 新项目沿用 `authentication.md` 的共享模型；存量项目优先局部适配。超出已授权范围的 Auth store、Session 来源、路由或数据/RLS 架构迁移，先说明差异、数据迁移和兼容风险并取得确认。
- 依次完成必要迁移、页面接线、云函数部署（如有），最后启用所需认证服务。模板不会自动生成业务表单、角色查询或测试用户。

## 业务接线与跨模块收尾

- 将认证示例适配为项目 UI 组件时，必须保留按钮的 `type`、事件处理、禁用条件和成功后的导航条件。替换前确认组件实际渲染的按钮类型及事件透传，不凭名称或外观判断行为；恢复步骤与按钮动作按 [恢复示例](recovery-flow-example.md#按钮接线契约) 核对。
- 修改前明确 SOP、动作参数与返回值、共享身份状态、页面步骤和导航负责人，并定位直接调用方及祖先路由。
- 动作参数、Auth 状态或 Gate 契约变化时，同步适配表单、Hook/store、页面与受影响的路由布局，再切换到无关功能。已有 Auth 状态源和动作对象优先复用，不因示例新增第二套 Session、监听器或业务初始化入口。
- 按 [状态职责](integration.md#状态契约) 区分 status、mode、step、authFlow。登录由身份状态导航；注册由成功步骤导航；恢复由保存、退出恢复会话、返回登录的顺序推进。按钮 loading 不能成为额外导航条件，祖先布局不能提前截断未完成的注册／恢复步骤。
- Web 认证导航的约束同样适用于存量／自写守卫（如 `RequireAuth`）：进入本次跳转分支时固定来源和目标，同一次尝试去重；路由 pending 期间旧守卫可能仍挂载，不能订阅全局 location 持续拼接 returnTo／redirect，也不能靠变化的 location key 重挂守卫。登录入口不得再次成为受保护来源，导航完成前保留等待态、不放行业务内容。复用现有 Auth Context 不免除这些约束；实现及检查点见 [Web 守卫导航契约](integration.md#web-守卫导航契约)。
- 合并当前行为中已明确的修改，允许按依赖分步编辑；接口需要调整时同步更新直接消费者。收尾时搜索旧参数、旧状态字段和重复跳转逻辑，执行受影响模块的类型检查及相关交互验证；不要求每次 Edit 全量构建，也不把“动作调用成功”当作整条链路完成。
- 中断或压缩时记录当前行为、SOP、准确接口契约、步骤与跳转条件、已改文件及版本、待适配调用方、验证结果、必要文档入口和下一步；涉及路由时保留已确认的 URL、父布局及导航负责人。不复制整篇文档，不保存密码、验证码、Token 或完整账号。恢复时核对文件变化，按上述读取规则补齐缺失内容，不据摘要猜参数或恢复认证授权；身份与恢复资格仍按流程核对。已确认模式、路由结构与能力状态沿用现有证据，不重复选型或启用服务。

普通退出按钮只处理 signOut 与反馈：受保护页由 AuthGate 在身份变为 anonymous 后导航，混合访问页默认留在原页切回游客视图，不因退出新增跳转；完整接线见 [业务示例](auth-signout-example.md)。恢复会话退出仍遵守独立流程的完成步骤。

## 邮箱／短信服务启用

先检查目标项目所需能力是否已开通；已有明确开通状态时复用，局部页面／Gate 修复不重复启用。只有首次接入或新增缺失的邮箱／短信能力时执行，基础密码方案遵守 `basic_auth.md`。启用可能触发重启，放在所有必要迁移、代码修改和云函数部署之后；状态不明先查询，不靠反复执行启用探测。

```bash
# 只启用已确认的能力；以下三条按需求选一条。
meoo-cli cloud enable-register-login --providers email --confirmed-provider-set
meoo-cli cloud enable-register-login --providers sms --confirmed-provider-set
meoo-cli cloud enable-register-login --providers email,sms
```

邮箱＋短信一次联合启用，不顺序单开；服务开通组合不等于同账号多凭据登录方案。完成前记录已有开通证据或本轮启用结果；失败停止启用流程并说明原因，“云服务变更中”不继续变更。实际触发启用／重启时提醒用户等待云服务面板完成后再测试；仅复用已有能力不声称正在重启，重启后仍失败按实际错误诊断。

## 验收与交付

以下验收适用于认证功能的实现或修改。仅创建测试账号时，按 [受控测试账号](test-accounts.md) 完成创建、指定初始化和凭证交付即可，不自动执行登录验证。

按对应流程文档验证正常路径、失败反馈、状态恢复和权限边界；登录必须验证提交后自动到达目标页且无需刷新，失败后解除 loading 并可重试；注册／恢复必须验证页面转换，不能只检查 API 存在。涉及登录／退出链路时按访问要求验证：受保护页退出后出现登录表单；混合访问页退出后仍可浏览公开内容、私有内容清空。检查无重复导航、无循环更新且退出后刷新不恢复旧身份；仅 204 或 build 通过不代表完成。认证事件先到时，普通登录应自动导航，注册确认及恢复应留在未完成步骤；必要业务收尾失败不能进入成功步骤。MFA 还需验证 AAL1 无法直接访问受保护数据。

逐项记录实现位置、验证方式及结果，区分“代码已接线”“模拟交互已验证”“真实邮件／短信端到端已验证”。缺少测试身份或验证码时完成其余检查，将相应端到端项标记 `BLOCKED`；模板注入、构建和服务启用不等于业务完成。持续未知错误、配置故障或跳转循环按 `auth-diagnosis.md` 排查，不以改文案或反复重试掩盖。

向用户说明功能和验证结果，使用“注册确认”“找回密码”等产品名称，不展开 provider-set 等内部术语。


## 已有复杂注册与详细路由排障

明确需要取消/身份世代隔离的多步骤收尾，或已有项目使用该 Hook 时，按需读 [注册流程](registration-workflow.md)，从固定子路径导入，普通密码注册不预读。详细路由历史指导保留在 [路由细节](auth-route-details.md)，有具体布局/恢复冲突才查。
