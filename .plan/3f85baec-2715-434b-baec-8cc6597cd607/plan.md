# 需求文档

## 应用概述（本轮为存量改动：语音电话第 4 步「观察层」）

在已交付的语音通话链路（A 录音 → B MiniMax STT → C 角色回复 → D TTS 播报）之上，加入**通话观察层**：本地分析每段录音的声学信号（停顿、语速、音量变化），可选调用音频情绪接口，把结果以"可能、推测"的口吻作为参考注入角色上下文——**情绪判断永远不是事实**，低置信度不注入，不做医疗诊断，角色不得宣称用户"一定"处于某种情绪。同时提供隐私控制：设置里可关闭情绪分析、一键删除音频缓存；界面如实说明数据是否离开设备、何时删除。

## 现状 vs 目标

- **现状**：每段录音结束即送 STT，`RecordedAudio.samples`（16k PCM）只在内存中用于置信度估算，页面退出即消失；没有任何会话级统计（总时长/停顿次数）；没有情绪接口；角色只知道文字内容，听不出"TA 犹豫了、声音变小了"。
- **目标**：说完一句话后，除了转写文本，还产出一份**本地声学观察**（本段停顿次数、最长停顿、平均语速、音量趋势）；若开启情绪分析且接口可用，附加一份**情绪猜测**（标签+置信度）；两者合成"通话观察"注入角色 system；界面上有诚实的观察卡；设置页可关情绪分析、可删音频缓存。

## 改动点说明

### 1. 本地声学观察（纯本地，数据不出设备）
新建 `src/lib/call-observe.ts` 纯函数层：
- `analyzeTake(samples, durationSec)`：按 20ms 帧算 RMS（口径对齐 stt.ts 的 estimateConfidence），RMS 低于静音阈值连续 ≥350ms 记一次停顿（句首句尾不计），输出 `{ pauseCount, longestPauseSec, speechRatio, meanVolume, volumeTrend }`；volumeTrend = 后半段均响 / 前半段均响（>1.15 渐强 / <0.87 渐弱 / 其余平稳）。
- `summarizeObservation(takes, emotion?)`：把多段指标写成中文观察文本，全部用"可能/似乎/推测"措辞，例如"这通电话 TA 共说了 12.4 秒，出现 3 次明显停顿（最长约 1.8 秒），说话时音量整体偏轻、后半段更轻——可能在犹豫，也可能只是环境安静或累了。"末尾固定一句"这只是声学信号的粗略推测，不准是常态，别当事实"。
- 情绪标签仅在置信度 ≥55% 时写入观察文本；低于阈值只保留声学描述。

### 2. 音频缓存与生命周期（回答"数据是否离开设备、何时删除"）
- 默认行为：**录音 WAV 只存在内存**，随页面退出消失；仅当用户在通话页手动点「保留本通电话的录音」才缓存到本机浏览器（IndexedDB，key `vp-call-audio`，上限 10 段自动滚旧），供回听/重转写。
- 情绪分析开启时，该段音频会**发送给所配置的情绪接口服务商**（这是唯一可能的出设备路径，界面横幅明说）；MiniMax STT 上传行为不变（B 步已有）。
- 设置页「删除音频缓存」：清空 IndexedDB 全部录音 + 本机观察统计，二次确认，删完显示"已删除 N 段"。

### 3. 可选情绪接口（失败静默回退，绝不阻断通话）
- 复用聊天 AI 通道：`chatCompletion` 走 OpenAI 兼容 `/audio/transcriptions`？——否。采用**网关通用协议**：优先尝试配置的独立"情绪分析地址+Key"（设置页可留空=不调用），请求形态为 multipart 音频 + 返回 `{label, confidence}` JSON；任何失败（超时 8s/非 200/字段缺失）→ 静默跳过情绪部分，观察卡只显示本地声学指标并标注"情绪接口未启用/失败"。
- 界面与注入文案都不把情绪标签伪装成模型权威结论，统一带置信度百分比。

### 4. 注入角色上下文
- `call-reply.ts`：`buildCallSys` 增加 observationText 参数，拼在 CALL_SCENARIO 之后、【最近对话】之前；`requestCallReply` 签名加可选 observation。
- 注入协议硬性约束（写进 system）：TA 只能以关心口吻间接回应（"你好像有点累？"），禁止断言"你一定是在难过"，禁止任何医疗/心理诊断式表述，禁止复述置信度数字。

### 5. 通话 UI（VoiceCallApp）
- 转写成功卡下方新增「通话观察」折叠条：展开显示本通累计（总说话时长、停顿次数、最长停顿、音量趋势）+ 情绪猜测行（若有）+ 数据来源脚注（"声学指标 100% 本地计算；情绪标签来自 XX 接口，可能不准"）。
- 「保留本通电话的录音」开关按钮（明示存到本机、可随时删）。
- 挂断时若缓存过录音，提示一行"本通录音已留在手机浏览器里，可在设置→通话观察删除"。

### 6. 设置页
- VoiceSection 之后新增 `CallObserveSection`（glass 卡 + Switch 模式，抄 NotificationSection）：本地观察开关（默认开）、情绪分析开关（默认关，开启需填接口地址/Key）、删除音频缓存按钮（二次确认红条）。

## 影响面与调用链

```
recorder.finish() ──> RecordedAudio.samples
        │                    │
        │              analyzeTake()  [新·纯本地]
        │                    ▼
        ├─(可选)──> 情绪接口 [出设备? 仅此项+STT] ──> {label, conf}
        │                    │
        │              summarizeObservation()
        │                    ▼
runStt ok ──> runReply(text, observation) ──> requestCallReply(cfg, ch, books, text, observation)
                                                   │ buildCallSys 注入【通话观察】
                                                   ▼
                                             LLM 回复 → TTS 播报（不变）
VoiceCallApp ──(手动)──> IndexedDB vp-call-audio 缓存 ←── SettingsApp 删除按钮
```
不受影响：聊天页 RoleChatApp 各链路、STT/TTS 协议、世界书、转账等卡片体系。

## 回归与兼容风险

| 风险点 | 是否破坏现有行为 | 兼容策略 | 回归测试点 |
|---|---|---|---|
| requestCallReply 签名变更 | 否（新增可选参数，缺省不注入） | 旧调用点零改动 | 关闭观察开关后通话链路与现在完全一致 |
| 情绪接口拖慢回复 | 可能 | 8s 超时+并行发起，回复不等情绪 | 关掉情绪开关时无额外延迟 |
| IndexedDB 不可用（隐私模式） | 否 | 捕获异常，按钮提示"本机存储不可用" | 保留录音失败不影响通话 |
| 观察文本让角色过度解读 | 用户可感 | system 禁断言协议 + "不准是常态"锚点 | 真机聊一轮看 TA 措辞 |

## 权限与失败回退（用户要求明确说明）

- **麦克风**：沿用 A 步——只在点「开始录音」瞬间申请，页面退出立即释放轨道；无后台监听。
- **数据去向**：声学指标（停顿/时长/音量）100% 本机计算、从不上传；录音本身只在内存，除非手动保留（存本机浏览器）；发送出去的只有两处——STT 转写（B 步既有行为）和情绪接口（默认关闭）。
- **删除时机**：内存录音随页面关闭即失；手动保留的录音永久留存直到用户在设置页点「删除音频缓存」；观察统计随缓存一并清除。
- **失败回退**：情绪接口失败/超时/格式错 → 静默降级为纯本地声学观察，通话流程零打断；IndexedDB 失败 → 提示并不落缓存；LLM 注入观察后回复失败 → 沿用现有重试链路。

## 验收标准

1. 录一段中间故意停顿两次的话 → 观察卡显示停顿次数≈2、最长停顿与实际相符，全程无网络请求参与该计算（断网也能出声学指标）。
2. 情绪开关关闭时，角色 system 不含情绪标签；打开且接口不通时，观察卡显示"情绪接口失败，仅本地指标"，通话照常。
3. 置信度低的样本（噪音/短录音）→ 观察文本里没有情绪词，只有"可能只是环境噪音"类中性描述。
4. 角色回复只会问句式关心（"是不是有点累"），不出现"你肯定在难过/你有抑郁症"式断言。
5. 点「保留本通电话的录音」→ 设置页「删除音频缓存」显示段数并可删干净（重进通话页无残留）。
6. 关闭"本地观察"总开关后，通话页不再出现观察卡，回复链路与第 3 步交付版一致。
7. `pnpm run build` + `tsc --noEmit` 全绿，单测覆盖 analyzeTake（人造静音间隔样本）与 summarizeObservation（低置信度不出情绪词）。

## 本期不实现

- 实时 VAD 连续监听、自动分段（用户明确按键启停）
- 声纹识别/身份判断、医疗或心理健康诊断类输出
- 情绪接口的多家服务商适配（先做一种通用协议，跑通再扩）
- 云端同步录音（vp-assets 不动音频）
